# Lucky Ordering Data Model Design

## Goal

Replace the template tables and routes with a clean starting point for a Luckin Coffee proxy ordering system.

## Confirmed Decisions

- Remove template `tasks` CRUD and the `dummy` example endpoint.
- Use two D1 tables:
  - `lucky_order_users`
  - `lucky_sellable_products`
- Expose POST-only CRUD routes.
- Pass every parameter through JSON request bodies, including ids for read, update, and delete operations.
- Generate all ids server-side as 10-character strings using only `a-zA-Z0-9`.
- Use soft delete by setting `is_delete = 1`.

## Table: lucky_order_users

Stores Luckin users that can place real orders.

Columns:

- `id TEXT PRIMARY KEY NOT NULL`
- `nickname TEXT NOT NULL`
- `token TEXT NOT NULL`
- `type TEXT NOT NULL DEFAULT 'lucky'`
- `status TEXT NOT NULL DEFAULT 'enabled'`
- `is_delete INTEGER NOT NULL DEFAULT 0`

Validation:

- `id` is generated by the API.
- `type` defaults to `lucky`.
- `status` must be `enabled` or `disabled`.
- `is_delete` is internal and defaults to `0`.

## Table: lucky_sellable_products

Stores product information that can be used for proxy ordering. Third-party fields are optional mapping values that may be supplied when a third party pushes order information.

Columns:

- `id TEXT PRIMARY KEY NOT NULL`
- `sellable_product_ids TEXT NOT NULL`
- `sellable_sku_codes TEXT NOT NULL`
- `sellable_quantity INTEGER NOT NULL DEFAULT 1`
- `order_user_id TEXT NOT NULL`
- `third_party_remark_id TEXT`
- `third_party_order_id TEXT`
- `third_party_product_id TEXT`
- `is_delete INTEGER NOT NULL DEFAULT 0`

Validation:

- `sellable_product_ids` is accepted and returned as a string array, stored in D1 as JSON text.
- `sellable_sku_codes` is accepted and returned as a string array, stored in D1 as JSON text.
- `sellable_quantity` defaults to `1`.
- `order_user_id` must reference `lucky_order_users.id`.
- `third_party_remark_id`, when present, must match `^[a-zA-Z0-9]{3}$`.
- `is_delete` is internal and defaults to `0`.

## Routes

Order users:

- `POST /order-users/list`
- `POST /order-users/create`
- `POST /order-users/read`
- `POST /order-users/update`
- `POST /order-users/delete`

Sellable products:

- `POST /sellable-products/list`
- `POST /sellable-products/create`
- `POST /sellable-products/read`
- `POST /sellable-products/update`
- `POST /sellable-products/delete`

## Response Shape

Keep the existing template response style:

- Success: `{ "success": true, "result": ... }`
- Error: `{ "success": false, "errors": [...] }`

## Testing

Replace template integration tests with tests for:

- POST-only route behavior.
- Server-generated 10-character ids.
- Default values.
- Soft deletes.
- JSON array serialization.
- `third_party_remark_id` validation.
- Foreign key validation for `order_user_id`.
